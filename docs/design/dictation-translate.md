# 设计：听写翻译（说中文打出英文，说英文打出中文）

2026-10-29。用途：和外国人聊天；给 Codex / Claude Code 下英文指令（英文效果更好）。
与 ⌥T（截图取字后翻译，docs/design/screen-text.md）共用 `polish.py` 的 `translate` 请求和同一份 prompt（`translate_system`）。

## 1. 实测

数据：创始人自己的 40 条真实中文听写（history.jsonl，按 App 分层抽样：Claude 18、微信 10、飞书 6、ChatGPT 2、
Kimi Code 2、Code 1、备忘录 1；中位 29 字，最长 495 字）+ 20 条英文听写样例（polish_eval / overdelete 的英文条目）。
质量：两轮、各两位盲评（不知道哪条出自哪个系统），1–10 分 =「能不能不改就发出去」，并标出必须改的错误。
两位评委打分相关系数 0.96。M5 Max；云端从北京直连 DeepSeek（deepseek-flash，关闭思考）。

| 方案 | 质量 | 必须改 | 中→英 | 英→中 | 松键后增加（中位 / p90） |
|---|---|---|---|---|---|
| 本机 Gemma 4 E2B，对 Light 结果再翻一遍 | 6.4–6.6 | 每 60 条 9–13 条 | 6.1 | 7.2 | **0.16 s** / 0.64 s |
| 本机 Gemma，从识别原文一步到位（润色 + 翻译） | 5.6 | 19–23 | 5.6 | 5.8 | 0.16 s / 0.61 s |
| 云端 DeepSeek，对 Light 结果再翻一遍 | **8.1–8.3** | **4–5** | 7.8–7.9 | 8.9 | 1.0 s / 1.3 s |
| 云端 DeepSeek，一步到位 | 7.5 | 9–11 | 7.1 | 8.4 | 1.1 s / 1.6 s |

- **先润色、再翻译** 两边都比一步到位好（本机 +0.9，云端 +0.7，必须改的错误减半）。Light 本来就在说话时
  逐段跑完，所以松键后只多一次翻译。
- **共用 prompt**：⌥T 的 `translate_system` 和我为听写单写的 prompt 打分相同（差 0.1–0.2，在噪声内），
  所以听写不另写 prompt。
- 本机的错误：意思译错或条件反了（「如果不太高」）、漏掉一个从句、人名被换掉（Alice → Bob）、把问题答了
  （「法国首都是哪」→「法国的首都是巴黎」）。云端剩下的错误多半是 Light 已经带进来的（漏掉的「嗯 / um」、
  听错的词）。两边都把「口喷鸡」译成 *spray chicken*，所以翻译要带上用户词表（见 §3）。
- **方向**：如果让模型自己判断往哪边翻，本机用我的 prompt 有 4/40 条中文原样返回，用共用 prompt 是 1/60；
  云端 0。语音模型本来就给每条听写判了语言（history 里的 `language`，Qwen3-ASR 的语言标签），
  把它作为 target 传过去，方向就不靠猜了。这是模型的判断，不是规则；识别器没给语言时才用 `auto`。
- **费用**（deepseek-flash：输入未命中缓存 ¥2 / 百万 token，输出 ¥8，高峰价；闲时减半）：每条翻译约 245 输入
  + 34 输出 token ≈ **¥0.0007**。创始人每天约 90 条（最多 155 条）：全部翻译每月约 ¥2–3，只翻三分之一不到 ¥1。
  这笔钱是在云端润色（每条约 ¥0.0013）之外另算的。

## 2. 建议

**Q1 目标语言：选 (c)，默认自动，设置里可以改。** 设置 → 听写 → 翻译成：自动（中 ↔ 英）/ English / 中文。
自动 = 用语音模型判出的语言，翻成用户两种语言里的另一种。
按 App 默认：**出厂不对任何 App 默认开启**。创始人 646 条听写里 384 条在 Claude 桌面版，而且是中文，
按类别预设一定会翻错。做法和风格一样：设置里有一个「总是翻译」的 App 列表；同一个 App 里手动开了 3 次，
就问一次要不要以后都翻（从不悄悄打开）。终端、Codex 要不要出厂就开，需要你定（§4）。

**Q2 触发：主要用说话中单按一下 ⌘，其次点刘海里的翻译标签。**

| 方式 | 结论 |
|---|---|
| 连按两下 ⇧ | 不用。单按 ⇧ 已经立刻切换「结构化」，要识别连按，每次单按都得等约 0.3 s 或者标签闪一下；连按两下本来就是「开结构化再关掉」；松键后马上再按 ⇧ 会漏给输入法，切换中英文。 |
| 单按右 ⌥ | 不用。听写键可以设成右 ⌥ 或任一 ⌥，会撞上。 |
| **单按 ⌘（左右都行）** | **主方式**。中文输入法不用单独的 ⌘，macOS 也不拿它做事。按住 Fn 时拇指就在 ⌘ 上。规则和 ⇧ 一样：按下、松开，中间没有别的键，且不超过 1 s，才算切换；⌘V 这类组合照旧。按住说话时也不打断。 |
| 刘海上的标签 | **次要方式**（Q3 本来就要这个标签）。点一下切换，和结构化的标签一样。 |
| 加进 ⌥L「重排上一条」的循环 | 不用。循环会变成 4 档；而且翻译和风格是两回事，「结构化 + 翻译」应该能同时开。 |
| 按 App 自动 | 这是设置（Q1），不是触发方式。 |

**Q3 刘海**：右耳在风格标签旁边加一个目标语言标签（EN / 中），打开翻译时才出现。
说话时字幕显示**原文**：用户看的是有没有听对，实时翻译会在说话过程中不停变化，还要每段多调一次模型。
松键后粘贴译文，刘海上照常显示「已输入」。前两次打开时会有一行提示（和结构化一样）。

**Q4 模型**：说话时 Light 照常逐段跑 → 松键后（开了结构化就在结构化之后）对整段调一次共用的 `translate`，
带上目标语言、词表和 App 类型（聊天 / 终端）。**已经设置了云端 key 就用云端翻译**（8.2 分，每条约 1 s），
本机作为后备（6.5 分，0.16 s）。翻译专用一个守卫：输出不能为空、不能有开场白、不能是回答，数字和词表里的词都要保留，
文字必须是目标语言；不通过就输入没翻译的文本，并在刘海上说明。

## 3. 需要对共用 prompt 做的两处小改动（⌥T 同样受益）

1. 可选的 `Words:` 一行（用户词表）：名字和术语照原样保留（口喷鸡 → Blurt，不是 *spray chicken*）。
2. 「去掉残留的语气词和口吃（嗯、um、uh）」：听写文本有时还带着它们，截图里的文字基本不会有。

## 4. 创始人的决定（2026-10-29）

1. **优先用云端，单独一个开关**（设置 → 听写 → 翻译 →「用云端模型翻译」，默认开；只有设置了云端 key 才生效）。
   有些用户连本机模型都没有（机器差、空间少，以后的 Windows / Linux），所以要有合理的降级和提醒：

   | 云端（开关开 + 有 key） | 本机润色模型 | 结果 |
   |---|---|---|
   | 有 | 任意 | 云端翻译；云端失败时有本机就用本机，没有就输入原文，刘海上说「没翻译成：…」 |
   | 没有 | 有 | 本机翻译（第一次用时提示一次：设置云端 key，翻译会更好） |
   | 没有 | 没有 | 不能翻译：按 ⌘ 或点标签时，刘海上说「翻译要用云端模型或本机润色模型」，并给出「设置」入口；不会打开翻译 |

   只用云端时不需要 MLX，也不需要下载模型（`polish.py serve` 不装模型也能起来，并且接 `translate` 请求）。
2. 终端、Codex 都**不默认**翻译：一律手动打开；同一个 App 里开过 3 次，就问一次要不要以后都翻。
   **v1.0.6 改为记住**：在某个 App 里按 ⌘ 打开翻译，以后在这个 App 里一直翻译，再按 ⌘ 关掉才取消；隔了一小时再用会提示一句「沿用上次的设置」。
   详见 `dictation-styles.md` §3.5。
3. 触发：**说话时单按 ⌘ + 点刘海标签**。

## 5. 做了什么

- **触发**（`BlurtCore/DictationTrigger.swift`）：说话时单按 ⌘（左右都行）→ `.translate`，规则和 ⇧ 一样：
  不超过 1 s、中间没有别的键；⌘V 这类组合照旧会打断按住说话；⇧⌘ 两个都不算；按 Fn 时 ⌘ 已经按着也不算。
  ⌘ 不会被拦下来，照常传给前台 App（单按 ⌘ 对 App 来说什么都不是）。
  刘海左半边（小鸡那边）点一下 = 翻译，其余地方 = 结构化（`.islandTranslateClick`）。
- **路由**（`BlurtCore/DictationTranslate.swift`）：
  - 翻成什么：设置里的目标；「自动」时取语音模型判出的语言的另一种。这个标签在 646 条听写里错了 2 条（0.3%），
    还有 9 条没有标签，这时交给模型自己判断（`auto`）。
  - 用谁翻：云端（设置了 key，并且「用云端模型翻译」开着）→ 本机润色模型 → 都没有。
  - 都没有的时候，按 ⌘ 只会提示，并给出「设置…」，不会打开翻译。
  - App 列表 + 「问一次」（某个 App 最近 10 条里有 ≥ 3 条、且 ≥ 70% 是手动翻译的）。
  - history 记下 `translate`：说的原话、目标语言、用谁翻的、是否降级及原因、耗时。
- **松键后**（`DictationStream.translate`）：按风格选出要输入的文本（结构化的就用结构化的）→ `Dictation.translate`
  （常驻的 polish 服务优先，没有就用 CLI；key 走 stdin）→ 译文替换原文，再套用 App 类型的变体。
  已经是目标语言的听写不发请求。
  翻译过的听写不参与 ⌥L 和 ≡ 建议：它没有同一种语言的其他版本可以切换。
- **polish.py**：⌥T 共用的 `translate` 请求多了三个可选参数：
  - `vocab`：只带出现在这段文字里的词，作为一行 `Words:`；
  - `spoken`：顺手去掉残留的语气词；
  - `check`：用 `translate_guard` 检查结果。云端被拒或失败就换本机；本机也不行就原样返回并标明原因，
    在刘海上说「没翻译成，已按原话输入」。

  ⌥T 本身的请求和 prompt 没变。没有本机模型（或没有 MLX）时，`serve` 不再强制装 MLX，只服务云端请求。
- **守卫**：只拦明显不是译文的结果，包括空、还是原来的语言、长度离谱（比例是在 240 条评过分的译文上定的），
  以及列表里拉丁字母的词丢了。评委指出的语义错误（漏一句、条件说反）都在这些界限之内，没有机械办法能查出来，
  所以守卫没有拦它们，也没有误拦一条好的译文。
- **刘海**：右耳显示 风格符号 + 翻译符号（`languages`）+ 计时；前两次打开时提示一行；
  第一次用本机翻译、又没设云端时提示一次。
- **设置 → 听写**：「翻译」（中文 ↔ 英文 / 翻译成英文 / 翻译成中文）和「用云端模型翻译」两行，
  下面列出总是翻译的 App，可以移除。没有云端时给出「设置…」，链到云端润色那一行。

### 端到端实测（2026-10-29，隔离的 App，M5 Max）

用一条真实录音当麦克风：先按一下 Fn，1.5 s 时按一下 ⌘，说完 0.1 s 后松开。每种情况跑两轮，第一轮用来预热。

| 录音 | 用谁翻 | 输入的内容 | 翻译耗时 | 松键 → 粘贴 |
|---|---|---|---|---|
| 创始人的真实听写：「另外，我自己手动提的几个 bug，你好像给遗漏了……」 | 云端 | *Also, it seems you missed a few bugs I filed manually. Those bugs need to be fixed too, and they'll take some work as well.* | 0.87–1.23 s | 0.93–1.27 s |
| 同上 | 本机 | *Also, the few bugs I manually reported, it seems you missed some of them, …* | 0.26–0.30 s | 0.29–0.36 s |
| LibriSpeech 真人英文录音（创始人没有英文听写） | 云端 | 婆罗门以为自己没救了，但又再次恳求老虎耐心一点，让他去问问第六位法官的意见。 | 1.0–1.2 s | 1.67–1.78 s |
| 同上 | 本机 | 婆罗门把自己当作迷失了，……（译错了） | 0.23–0.24 s | 0.83 s |

两个方向都按语音模型的标签判对了（zh → en，en → zh）；`said` 原话也记进了 history。
数据和脚本：`promo/cases/dictation-translate/`（`e2e.py`、`e2e-cloud.jsonl`、`e2e-local.jsonl`、`audio/`）。

「都没有」那条路也端到端跑过（没有润色模型，测试 key 为空）：按 ⌘ 后刘海提示
「To translate, set up a cloud model or download this Mac's polish model」，并给出「设置…」；翻译不会打开，听写按原话输入。
刘海截图（只截隔离 App 自己的刘海窗口，中英文各一套）：`promo/cases/dictation-translate/shots/`。英文那行原来折成两行，
已改短为「Translating: Chinese ↔ English · ⌘ to turn off」。没跑三评委视觉评审。

## 7. v1.0.6：更多语种

- 「设置 → 听写 → 翻译成」：「自动：中文 ↔ 英文」（默认，和以前一样），或 English、简体中文、繁體中文、日本語、
  한국어、Français、Deutsch、Español、Português、Italiano、Русский（用各语言自己的写法列出）。⌥T 截图翻译共用这一个
  设置（创始人选的方案：一个「翻译成」列表）。
- 说的已经是目标语言：翻成系统的第一语言（`DictationTranslateRoute.home`），两者相同就不翻。听写知道说的是什么语言
  （语音模型给出），直接定方向；⌥T 和没判出语言的听写把两个都交给模型：polish.py 的 target 写成 `X|Y`（翻成 X；
  已经是 X 就翻成 Y），守卫只在原文确实是 X 时才接受 Y。
- 实测（DeepSeek V3.1，经 OpenRouter）：中文、英文句子翻成日语、法语都对；目标英文、原文英文时翻成了中文。本机
  润色模型在中英以外的语言上没测，设置里的说明写「用云端更好」。
