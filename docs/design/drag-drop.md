# 设计：拖进、拖出、多选——卡片不只是截图

2026-11-15，1.0.23。来自创始人当天的使用反馈：

1. 刘海下挂着的卡片拖不进主窗口，只能拖到刘海里的项目列表。
2. 带备注的卡片拖进 Claude Code / Codex，只进去一张图，备注丢了（1.0.21 做的「路径 + 备注」好像没生效）。
3. 想把浏览器里的图、访达里的文件（PDF、视频，甚至多个）直接拖到主窗口或刘海：刘海里挂成卡片（可加备注），主窗口里直接成条目，
   拖到已有条目上就是给它加图。不同区域要有不同的、看得见的结果。
4. 挂了很多卡片时，能任意挑几张（1、3、5、7）一起拖：拖进 Claude Code / Codex、拖进某个项目。
5. Windows / Ubuntu 也要跟上。

## 0. 两个 bug 的根因（先修）

### 0.1 备注丢了：探针把「通知中心」当成了目标 app

拖动时 Blurt 要知道指针下是哪个 app（终端 / agent 拿「路径 + 备注」一行字，聊天 app 拿图、松手后再贴备注……）。探针按
CGWindowList 的前后顺序找指针下第一个不是我们的窗口。macOS 26.5 上通知中心常驻一个**全屏、完全透明、layer 21、alpha 1**
的窗口，盖在所有 app 上面。于是今天每一次拖动的目标都是 `com.apple.notificationcenterui`（card-drag.log：11-15 的 4 次全是它；
11-12 拖进 Claude / Codex 时还是 `claudefordesktop` / `codex`，Code 页签拿到的是 `terminal`，结果 `paths`）。通知中心被当成
「不认识的聊天 app」：拿到的是图，松手后找不到输入框（`skip("not_text")`），备注只进了剪贴板。

修法（BlurtCore `DropWindows.pick`，有单测）：Dock 层以上（layer > 20：通知中心、菜单栏和状态栏项、拖动图像、光标）的别家窗口
永远不是落点；系统浮层进程（通知中心、控制中心、台前调度、聚焦、截图 UI、输入法浮窗）在任何层都跳过。

### 0.2 卡片拖进主窗口没反应

探针跳过**所有**我们自己的窗口，所以指针在主窗口上时，拖动板按主窗口**后面**那个 app 重写——后面是终端或 agent 时，第一项是
那一行字，没有卡片标签（`dev.blurt.capture`）；侧栏和列表只读第一项的标签，于是什么都不做。

修法：只有拖动中不接鼠标的卡片面板才透过去；主窗口、刘海、备注气泡是「我们的」——指针在上面时拖动板写成第一项带标签的布局，
主窗口和刘海的接收方读**每一项**的标签（多选拖动带多个标签，§2）。

### 0.3 拖进 Claude Code / Codex 有时还是图片文件（真机试用后，2026-11-15 晚）

- Claude 的 Code 页签、Codex 模式要靠读窗口的 Accessibility 才认得出（AgentWindow）。这次读是在主线程同步做的：
  Electron 刚被唤醒时要 ~1.5 s 才给出页面地址，期间一直判成「聊天」——快速松手就拿到图片文件 + 贴备注；
  而且每次读都卡住主线程，拖动图像跟不上鼠标约 1 秒（Claude 全屏在卡片后面，一开拖就碰上）。
- Codex（Chromium 系）在指针**进入**窗口那一刻就把拖动数据读走了：日志里它 15.788 读了图片文件，Blurt 76 ms 后才改写成
  「路径 + 备注」，已经晚了，备注也就没了。
- 修法：探测挪到后台队列，答案跨拖动保留；卡片放下来时、开始拖时就先探一遍（AgentProbe.prewarm）；从没探过的 app 当场同步探一次；
  答案变了立刻改写拖动板。另外第一项多声明一个「备用」类型（图片布局也声明文字，agent 布局也声明图片），每个类型给什么仍在被读的那一刻
  按读它的 app 决定——先进入的 app 也能拿到对的东西（真终端不加：它在松手时才读，可能挑空的文件 URL）。

### 0.4 外部内容拖进刘海、拖进主窗口都没反应（真机试用后，2026-11-15 夜）

第一版这两条只用测试钩子验过，没做过真的鼠标拖动。真机上一试就不行，各有一个原因：

- **刘海不接**：接收用的小窗口（DropCatcher）是全透明的。macOS 把透明像素上的鼠标事件和拖动都交给下面的窗口，所以小窗口
  出现了（日志有 `drop_watch`），拖动却从它身上穿过去。修法：`ignoresMouseEvents = false`，再铺一层 alpha 0.02 的底色。
- **主窗口只认启动后的第一次拖动**：`ItemTableView` 和 `DetailWebView` 的 `draggingEnded` 里调了 `super.draggingEnded`，
  而 NSTableView、WKWebView（连 NSView）都没有这个方法。第一次拖动结束时抛异常，窗口的拖放状态卡住，之后所有拖动都不再送进来
  （日志只剩 `CoreDragRequestDragCompleteMessage: -1850`）。修法：去掉这两个 super 调用。
- **拖到第一行变成「新建」**：「松手新建」那条横幅盖在列表最上面一行上。现在横幅挪到列表上方（盖住搜索框），自己就是一个接收区，
  不再挡任何一行。
- 验证方式也改了：一个自己的拖动源小窗口（文件 URL、文件承诺 = 浏览器图片、TIFF 数据、文字）+ 真的鼠标事件，对着隔离的测试 app
  拖。刘海（直接松手、抽屉里「挂到刘海下」「未归类」两行）、列表空白处、第一行、横幅、侧栏、详情页，连续多次都过了。
- 这些拖放事件现在也写进 `~/.blurt/logs/card-drag.log`（`drop_watch`、`drop_external`、`drop_hang`、`main_drop_over`、
  `main_drop`、`detail_drop_over`、`detail_drop`、`item_drop_add`、`main_paste`），下次没反应有据可查。

### 0.5 拖进飞书只有图片，没有备注

不是这一轮弄坏的：飞书（Chromium，不是 Electron）平时不把输入框给 Accessibility 看，Blurt 找不到输入框就不敢贴，备注只进了剪贴板
（提示「备注已复制，⌘V」）。11-12 那次能贴上，是因为当时它的 Accessibility 树碰巧已经醒了。
现在卡片拖进飞书窗口时，Blurt 给它设 `AXEnhancedUserInterface`（读屏软件用的开关；调用返回「未实现」但实际生效——实测设之前
263 个元素、没有输入框，之后 1071 个、有输入框），松手后最多等 2 秒找输入框，找到就贴；8 秒后把开关关回去（树还在）。
**没验证的部分**：飞书刚启动、树还没醒时要多久才找得到（本机这个飞书进程在测试里已经被唤醒了，不能再测冷启动）。

### 0.6 ⌘V

主窗口里 ⌘V（焦点在列表或侧栏）：剪贴板里的文件、图片、文字 → 打开「新建事项」，内容已填好，↩ 创建（以前只有列表有焦点时
认图片和文字，文件不认）。焦点在详情页、剪贴板里是文件或图片：直接加到正在看的事项（带撤销）；是文字：照旧贴进页面的输入框。
从 Word / Excel 复制的内容按文字算（它们会顺带放一张图）。在 Blurt 里复制的行和卡片不会被贴成重复的文件。

## 1. 原则

- **一个手势，一个结果，松手前就看得见**。拖到哪里会发生什么，在松手前用一句话说出来（落点高亮 + 一个小标签：「新建条目」
  「加到 AW-14」「挂成卡片」「归入 Blurt」）。没有确认对话框；有撤销。
- **区域即意图**：刘海 = 先挂着（没想好放哪）；主窗口列表空白处 = 新建条目；已有条目 = 加进去；侧栏项目 = 放进那个项目。
- **文件引用，不搬文件**：PDF、视频、压缩包等只记路径（加一张缩略图方便认）；图片例外——拷一份进来，因为它要能画标注、
  烧备注、在原图被删后照样能用，而且浏览器拖来的图本来就没有路径。
- **卡片怎么出去，跟它是什么无关**：图片卡、文件卡、文字卡、多选的一组，进终端 / agent 都是「每张一行：路径，然后备注」，
  进聊天 app 都是「先东西，再备注」，进访达都是文件本身。

## 2. 多选（刘海下的卡片行）

- **⌘-点击**：加入 / 移出选择。**⇧-点击**：从上一次点选的那张到这张，连成一段。键盘多选在主窗口的卡片页（⌥H）：
  **⌘ / ⇧-点按**、**⇧ 方向键** 扩选、**⌘A** 全选一节、**↩ / ⌘C** 复制选中的全部、**⌫** 删除、拖出整组（`CardSelection`）。
- **顺序就是点选的顺序**（一段、全选按时间从早到晚），卡片角上的徽标写 1、2、3——出去的顺序、聊天里备注的序号都按它。
  （评审：按挂的顺序是最新在前，给 agent 的复现步骤是倒着的。）
- **不再每点一下就覆盖剪贴板**：停手 0.6 秒后整组复制一次（行下方「已选 3 张 · 已复制」）；剪贴板管理器里不再多出 4 条。
- 卡片收起来时选择保留 1 分钟（沿着一长排挑 1、3、5、7 会碰到收起）；普通单击、拖出、归档、或 1 分钟后结束。
- **拖动选中的任意一张 = 拖走整组**：拖动图像是一叠（最多 3 张，错开 4 pt、±2°），数字是系统自己的角标（一张卡一个拖动项）。
  拖未选中的卡片只拖它自己，选择不变。
- **⌥ 拖**（松手时按着 ⌥）：复制拖——卡片留在绳上，同一组可以再给第二个 agent。

整组拖出去，各类 app 拿到的（BlurtCore `CardPasteboard.drag(into:cards:)`，每张卡一个拖动项，每项都带卡片标签）：

| 落点 | 拿到的 | 之后 |
|---|---|---|
| agent 自己的输入框（Claude 的 Code 页签、Codex、WorkBuddy、QoderWork、Kimi Code、豆包工作） | 一段文字，每张卡一行：`'<路径>' <备注>`（文件卡是原文件路径，文字卡只有字） | 不贴、不动剪贴板 |
| 终端、AI IDE（Cursor、Windsurf…可能落在内置终端） | 同上但**一行**（卡与卡之间两个空格）：shell 提示符里的换行会执行命令 | 同上 |
| 聊天 app（浏览器、飞书、微信、Slack…） | 所有图片 / 文件，按选择顺序 | 备注作为一段贴进输入框：多张时 `1. 备注`，序号 = 第几个文件；没有输入框焦点（发送确认框、Figma 画布）就只进剪贴板 |
| 富文本 app（备忘录、文本编辑、邮件） | 一个富文本项：图、备注、图、备注…… | 无 |
| 访达 | 所有文件；文件卡**只允许拷贝**（绝不移动原文件） | 备注进剪贴板 |
| 主窗口 / 刘海的项目 | 整组归档进那个项目 | 「已归入 X」 |

被接收后整组离开绳子（进「最近拖出」7 天），一个提示「已拖走 3 张 · …  撤销」，撤销一次放回全部。

## 3. 拖进刘海：挂成卡片

- **不误触**：只在拖动板里有我们接的类型（文件、图片、文字、链接）且不是 Blurt 自己的拖动时才准备接。刘海外扩 8 pt 内：刘海微微变高
  （提示「这里能放」）；停留 250 ms 才展开**接收抽屉**；离开抽屉 300 ms 收起。用一个独立的小「接收面板」（刘海 + 40 pt，随抽屉变大），
  拖动结束就撤掉——不把 640×470 的刘海窗口整个变成落点（会吞掉浏览器标签栏的拖放）。别人的拖动期间卡片面板保持鼠标穿透。
- 抽屉：标题说清楚拖来的是什么「挂成 3 张卡片」；第一行是大的「挂到刘海下」，下面是最近的项目、未归类。拖的是卡片时没有「挂」这一行。
  外部拖动永远回答「拷贝」（绝不「移动」：源 app 会把原文剪掉）。
- 松手：
  - 图片（文件、浏览器的图片承诺、图片数据）→ **图片卡**：后台导入，按 EXIF 转正、长边最多 6000 px、写成 PNG；先挂一张占位卡。
  - 其他文件 → **文件卡**：卡面是 Quick Look 缩略图（拿不到就用图标），底部写文件名；引用原路径（`"ref"` + 书签，原文件被挪走也能找回）。
    **临时位置的文件拷一份进来**（`/var/folders`、`TemporaryItems`、`~/Library/Caches`、各 app 的容器、正在下载的 `.download`）：
    飞书 / 微信缓存里的 PDF、⌘⇧5 的录屏缩略图一会儿就没了。删卡片绝不碰原文件；原文件不见了卡片上写「找不到原文件」。
  - 文字、链接 → **文字卡**。Safari 地址栏拖来的 `.webloc` 当链接。文件夹不收（标签说「文件夹请拖到侧栏，打开为项目」）。
  - 多个 → 每个一张卡，顺序同拖来的顺序；**不**自动成选择（会动剪贴板）。
- 只拖来一样东西时，挂上后备注气泡打开，但**不抢键盘**：指针移到气泡上（或点它）才接打字；没打过字 6 秒自己收起，打过字的不会自己关、
  关时保存。拖来多样时不弹。
- 松在项目上：直接归入那个项目。

## 4. 拖进主窗口

| 落点 | 外部的图 / 文件 / 文字 | 挂着的卡片（一张或一组） | 列表里的条目 |
|---|---|---|---|
| 侧栏的项目 / 未归类 | 新建条目表单，项目选好 | 归档进去 | 移动（已有） |
| 列表顶部的「松手新建条目」条（拖动时出现，44 pt）、列表空白处、空列表 | 新建条目表单（当前视图的项目；按项目分组时是指针下那组） | 归档进当前视图的项目 | — |
| 列表里某个条目上 | **加到这个条目**：图片成为截图帧，文件进「附件」，文字接在详情后面 | **加到这个条目**：卡片的图（或文件）+ 备注，卡片离开绳子 | — |
| 右侧详情 | 同上，加到正在看的条目（文字拖进页面里的输入框照旧是输入框的） | 同上 | — |

- 列表满的时候没有空白处，所以拖动时列表顶部钉一条「松手新建条目」——不然每次都只能「加到某条」。
- 指针旁的小标签说结果，用条目标题不用编号：「新建条目」「加到「首页竞品」」「归入 Blurt」「只读条目，不能添加」「2 个文件 · 文件夹不收」。
  光标角标：新建 / 加图 = 拷贝（+），只有引用文件 = 链接，归档卡片 / 移动条目 = 移动。
- 新建条目表单：标题框有焦点，**↩ 直接创建**；只有文件时标题预填第一个文件名。文件显示成「图标 + 文件名」一行行，可以 ×。
- 加到已有条目：不弹窗，那一行闪一下，提示「已加到「首页竞品」 · 2 张图 · 撤销」。撤销 = 恢复加之前的帧 / 附件 / 详情（`items.py attach --restore`）。
- 键盘：列表里 ⌘V 新建条目（已有）。

条目的引用文件存为 front-matter `attachments: ["/abs/path.pdf", …]`（绝对路径；临时位置的文件拷进 `assets/<uid>/` 再引用那份）。
图片帧一律拷贝（不硬链接用户的原图）。交接包、MCP `get_item`、详情页都读它。
