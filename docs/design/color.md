# Colour system (v0.8 proposal): mint is the brand

> **中文摘要**
> 品牌色从珊瑚橙（`#F55B3E` / `#FF7A5C`）换成灵动岛听写电平的**薄荷绿 `#61DBBD`**，但只用在"口喷鸡正在听 / 正在截 / 替你动手"的时刻，以及每屏唯一的主按钮。规则：
> 1. **薄荷 = 活的时刻**：框选区域的虚线、手柄和尺寸标签，窗口悬停，截图闪光环，灵动岛的听写和语音电平，挂卡的扣子，被选中的卡，"新 / 进行中 / 交给 agent"的状态环，主按钮，选中行的底色。
> 2. **红 = 正在录**：开始录屏后边框从薄荷变红，暂停变琥珀色虚线。**琥珀 = 要你处理**，**叶绿 + ✓ = 完成**（从原来的绿色往黄绿方向挪，和薄荷拉开，并且永远带勾），**红 = 出错 / 危险操作**。
> 3. 浅色界面上薄荷只做**填充**（配深绿字 `#04261E`，9.5:1）；线条和文字用**深薄荷 `#0B735E`**（白底 5.8:1）。深色界面和灵动岛直接用 `#61DBBD`。
> 4. 系统控件（开关、焦点环、文字选区）继续跟随系统强调色，不声明 AccentColor。
> 5. 珊瑚退出品牌，但保留两个用处：**画笔**（烧进截图的批注）和 **issue 类型色**。task 类型从绿色改为紫色，避免和薄荷、完成色撞。
> 6. App 图标**保留黄色底**：黄色代表"这个 app / 下载"，薄荷代表"它正在帮你干活"。
> 7. 实施：新建 `assets/color/tokens.json` 作为唯一来源，生成 Swift `BrandColor` 和 CSS 变量；本文末尾列出了所有要替换的硬编码颜色。

## 1. Why, and the one rule

The coral accent is a common colour and says nothing about blurt. The mint already exists in one place, the dictation
level on the notch island (`Ears.swift` `dictationTint`), and it is the moment the product is about: *blurt is hearing
you*. So mint becomes the brand, with one meaning:

> **Mint marks blurt in the act**: listening, capturing, or about to act for you. Plus the single primary action on a
> screen, and the selection in lists blurt draws. Everything else is neutral or a semantic colour.

If a new use of mint can't be described by that sentence, it doesn't get mint. A screen with three mint things is
usually wrong.

## 2. Tokens

Contrast is WCAG 2.x relative luminance. Floors: **4.5 : 1** for text, **3 : 1** for icons and UI strokes.
"Light surfaces" are `#FFFFFF / #F6F6F6 / #ECECEC` (panel, bg, bg-2); "dark surfaces" are `#1E1E1E / #2A2A2A / #323232`.
The island and the capture chrome are always dark (black / 82 % glass), so they get an `island` value.

the same hue (OKLab h ≈ 174°) at a usable luminance. In dark mode one value does both.

**Success vs mint.** Today's "keep" green (`#15965F` / `#2B9466`, OKLab h 158°) and task green (`#218358` / `#3DD68C`)
sit 15–20° from mint and would read as brand. `ok` moves to a leaf green, h ≈ 134° (light `#3F7414`) / 132° (dark

greens are never fully safe for colour-blind users, `ok` is also a shape rule: done is always a filled disc with a
check (the state ring already is), "Saved" always has a check glyph. Nothing is "done" by colour alone.

### 2.4 Neutrals

Unchanged: the platform surfaces in `web/packages/ui/src/tokens.css` (mac `#F6F6F6 / #ECECEC / #FFFFFF` light,
`#1E1E1E / #242424 / #2A2A2A / #323232` dark; text 85 / 70 / 56 / 32 % black, 92 / 78 / 64 / 40 % white; hairlines 8 %),
the island black, the capture glass (`white: 0.05–0.08, alpha 0.72–0.82`). Neutrals do not get tinted toward mint;
the discipline is that most of the app is grey.

Native macOS controls (switches, checkboxes, popups, segmented controls, focus rings, text selection, the source-list
highlight's *focus* state) keep the **system accent**. The app does **not** declare an `AccentColor` /
`NSAccentColorName` in phase 1: mint on every switch is exactly the "wherever you think of it" use, and the user's
accent choice is theirs. (Phase 2 option: declare it as `brand.ink` light / a deeper `#0F7F67` dark so that only
Multicolor users get it; not recommended now.)

### 3.4 Settings and onboarding

Settings are the most "native" surface and get the least brand: switches, checkboxes, popups and focus rings are
system. Brand appears only where something is listening or recommended:

- the **mic test meter** in Speech / Dictation: mint bars (dark) / `brand.ink` (light); idle bars neutral;
- the **"Recommended" / "Runs first" badges**: `brand.tint` background, `brand.ink` text;
- the **selected choice card** (dictation style, model): 1.5 pt `brand.ink` border + `brand.tint` ring, not a filled
  card;
- the **hotkey recorder while recording a shortcut**: `brand.ink` border and text (it is listening to your keys);
  conflict → `attnInk`;
- **onboarding**: step progress bars `brand.ink`, the primary "Continue" button mint; permission rows that are granted
  get the `ok` check, missing ones an `attn` dot;
- `Color.accentColor` in SwiftUI views stays only where the meaning is "native control"; every other use moves to an
  explicit `BrandColor` (see the migration table).

### 3.5 Menu-bar icon

None. `glyph.svg` is a template image and stays monochrome; it carries "listening" by motion only (the arcs pulse).
The recording status item keeps its `rec` dot and time; paused `attn`.

### 3.7 Never brand

- body text, titles, labels, placeholders (neutral `ink` tiers only);
- large backgrounds: window, sidebar, panel, island body, card faces, the site paper; mint tints only at row scale;
- warnings, errors, destructive actions (attn / err / system red);
- recording itself (red) and paused (amber);
- native controls (system accent);
- the menu-bar glyph (template);
- the pen (markup coral) and anything burned into a screenshot;
- decorative illustration fills (the egg / chick art keeps its own colours);
- charts and data series (use the dataviz palette, never brand as a series colour).

## 4. Motion and colour together

One visual language for "blurt is with you":

| Moment | Colour | Motion (Reduce Motion: the still frame) |
|---|---|---|
| Listening (dictation, voice note, mic test) | mint bars | bars follow the level; on silence they settle to 2.5 pt dots, never disappear |
| Choosing an area | mint dashes, handles, label | the dashes march slowly while dragging; still otherwise |
| Choosing a window | mint outline + wash | 120 ms fade-in on hover change |
| Countdown | red ring | ring drains per second; the area outline cross-fades mint → red at 0 |
| Recording | red border, red dot | the island dot breathes (1.6 s); the border is still |
| Paused | amber dashed border, amber dot | no motion: stillness is the signal |
| Snap taken | white shutter (standalone) / mint ring + glow (while recording) | 320 / 450 ms flash, once |
| Card hung | mint clasp | the card swings in; the clasp does not animate |
| blurt working (agent running, organising) | mint spinner arc / mint dot | quarter arc rotates (1.1 s) |
| Done | `ok` + check | the chick hops / the check draws once; colour never pulses |
| Needs you | `attn` | a single pulse when it first appears, then still |

Rules: at most one mint thing moves at a time on a screen; mint never blinks for an error or a warning; red only ever
means recording or error, never "active"; and every coloured state has a shape twin (dashed vs solid, dot vs ring,
check vs "!") so it survives grayscale and Reduce Motion.

All values in sRGB (`NSColor(srgbRed:…)`), not calibrated RGB (today `accent`, `amber` and `dictationTint` are
calibrated, so the same hex renders slightly differently from the web). `StatusRing.accent / attention / keep`,
`KindStyle.palette`, `Look.brand`, the global `accent` / `amber` and `EarSlot.dictationTint` become thin aliases for one
release, then go.

Generated CSS (sketch): the shared block of `tokens.css` writes `--brand`, `--brand-ink`, `--brand-tint`,
`--brand-glow`, `--on-brand`, `--rec`, `--attn`, `--attn-ink`, `--on-attn`, `--ok`, `--on-ok`, `--err`, `--info`,
`--markup`, `--kind-*` for `[data-theme="light"]` and `[data-theme="dark"]`, plus the deprecated `--accent*` aliases.

The check (`build.py --check`, run from `tests/`) verifies every `min` against `checks` and that kind colours have 3 : 1
on `kindSurfaces`, the same arithmetic `KindStyle.contrast` and `contrast.ts` already use.
