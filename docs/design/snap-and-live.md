# 设计：截图模式、下蛋动效、顶部鸡舍、分层提速

2026-10-21。面向 vibe coder：一边点自己做的东西一边说，说完马上拿到能交给 agent 的条目。
总原则不变：**录制中绝不打断**；要停，只能是用户自己按的。

## 1. 截图模式：「一张图 + 一句话」

同一个概念，两个入口。快捷键 **⌥⇧A**（Windows/Linux `Alt+Shift+A`，和微信/QQ 截图的 Alt+A 一致，好记）。

### 1a. 单独截图（没在录屏时）

1. ⌥⇧A → 复用录屏的选区遮罩：拖一块 / 点一个窗口 / F 全屏 / L 上次区域。**松手即截**（像 ⌘⇧4），不需要再点「开始」。
2. 快门：选区闪一下白光（可选快门声），截图缩成卡片，弹簧动画飞到屏幕顶部的**鸡舍**（§3），挂在绳子上。
3. **自动开麦**：卡片下方弹一个小气泡「🎙 在听… 说完停一下就好 · 直接打字也行 · Esc 跳过」。
   - 说完约 1.8 秒静音自动收尾；8 秒没开口就当没有备注；最长 60 秒。
     「静音」是相对房间底噪说的（v0.8，BlurtCore `NoteEndpointer`）：底噪取最近 3 秒 20 ms 帧的第 10 百分位，说话时也跟着走；
     麦克风刚打开的 0.25 秒（比房间安静）不算。v0.7 把底噪定在开麦头 0.3 秒、说话后冻结，正常房间（约 −42 dBFS）永远不算静音，备注停不下来。
   - 开口后又改打字：继续听到停顿为止；说话不到 1 秒就当放弃语音，录音丢掉。留下的录音一定转写（打了字也转）；转写为空（只有房间声）也丢掉录音，卡片上不出现麦克风。
   - 开口前直接打字就切成文字输入（麦克风停），Enter 保存。用户刚截完图，这一下抢焦点可以接受；保存后焦点还给原来的 App。
   - 气泡开着时，截图放大预览，**按住 ⌃ 拖动**可以在图上圈画（和录屏画笔同一手势），笔迹另存一份 `*.marked.png`，原图保留。
     （v0.9-next 起改为原地标注：选区冻结在原处直接画，拖动 / ⇧ 方框 / ⌥ 椭圆，见 next-round.md K7 细则「原地标注」。）
   - 备注没收尾时再按 ⌥⇧A：先保存当前备注，再截下一张。连续截几张不需要任何确认。
4. 一批截图属于同一个 session：`<workspace 的 sessions 目录>/<ts>-shots/`，第一次截图时创建。点鸡舍上的「🐔 整理 N 张」才开始处理，处理后开新的一批。
5. 可选（菜单开关，默认关）：**收集系统截图**，把 ⌘⇧3/4/5 截的图也挂到鸡舍上（同 Tendedero），不带备注，双击可以补。

为什么要这个模式：很多反馈是一个画面加一句话，录一段视频太重了。截图是全分辨率的、就是证据本身，不用从视频里挑帧，处理会快很多。
缺点是看不到操作流程和动画，所以视频模式要保留，说明里也要讲清楚怎么选。

### 1b. 录屏中截图

需要：视频帧经过压缩，agent 挑帧靠猜。按一下截图就是「就是这一刻、就是这个画面」，信号比画笔还强，而且是全分辨率。

- 录屏中 ⌥⇧A（⌥⇧M 标记也一起升级成截图）：**不暂停，不弹输入**，直接截下录制区域的全分辨率静帧。录制区域的边框闪一下（边框不在录制范围内）。
  缩略图飞进悬浮条，悬浮条上显示 📸 计数。
- 这张图的备注就是前后大约 15 秒说的话。你本来就在说话，再停下来补录会打断思路。
- 想打字补充：点悬浮条上的 📸 打开备注框。**打开时自动暂停，关掉自动继续**，和放弃录制的确认框一样。只有主动点开才会暂停。
- agent 端：每张截图都要锚定一条条目（和画笔一样，优先级高于对模糊语句的理解），这张截图作为该条的首帧。

## 2. 动效隐喻：下蛋，不用虫子

- **一条 = 一个蛋**。口喷鸡下蛋，天然成立，而且不分种类：
  - issue：带小虫斑点的蛋
  - idea：**金蛋**（金点子）
  - note：白蛋
  - task：带勾形纹的棕蛋
  - 自定义 lens：淡彩蛋
- 虫子只适合 issue，而且录屏时屏幕上爬虫子会让人焦虑。留给以后的「修好了」时刻：鸡把虫啄掉。
- 蛋**用代码画**（CoreGraphics 矢量：渐变、高光、斑点），不用位图素材：Retina 清晰，深色模式也好看，官网上可以用同样形状的 SVG。
- 出现的地方：
  - **录屏中**：实时草稿（§4）每识别出一条，就有一颗蛋落进悬浮条的小窝里，轻轻弹一下，显示「🥚 6」。**录屏中不出声**，否则会录进麦克风。
  - **录完 / 点了整理**：鸡舍上的蛋轻轻晃动（孵化中），整理完成后通知用户并打开审核页。
  - **审核页 / 截图卡片**：用对应种类的蛋做标识。

## 3. 顶部鸡舍（the Perch）：向 Tendedero 学习

屏幕顶部菜单栏下方一根米色麻绳（两端系在小木钉上），截图像拍立得一样被**鸡爪夹子**夹着挂在上面。鸡爪夹子是我们自己的细节，和 Tendedero 的晾衣夹区分开。

- 平时隐藏。新截了一张图时滑下来，停 3 秒后收回。指针在顶部中间区域停留超过 250 毫秒时滑下来。⌥⇧B 菜单里有「显示鸡舍」。指针离开 400 毫秒后收回。
- 动效：
  - 绳子是一根阻尼弦（Rope.swift）：挂的卡片越多越往下坠（越重越绷，下垂增长放缓），卡片坐在绳上、随所在处的坡度倾斜。挂上一张时那里一沉、绳子弹几下；拿走时弹回；悬停提起的卡片不再压着绳子，那里升起一点；鸡舍滑下来时绳子也晃一下。1–2 秒内停稳，停稳后不再逐帧刷新。
  - 卡片挂上去时像钟摆一样晃几下，然后停住（阻尼弹簧）。
  - 悬停时卡片抬起、停止摆动，左右的卡片用弹簧让位。
  - 拖出去时有惯性。删除时卡片受重力掉出屏幕。
  - 系统开了「减弱动态效果」就改成淡入淡出，绳子只有静态的下垂。
- 卡片手势：
  - 单击：复制图片（有笔迹就复制带笔迹的那张）。
  - 拖动：拖出文件，可以拖进 Claude Code、聊天窗口或 Finder；有备注的话，同时以文本形式提供。
    v0.8：图片和备注是两个独立的剪贴板条目（之前文字挂在图片那一条上，多数 App 只拿文件，文字就丢了）。拖出的文字是一行（`打的字 · 说的话`、去掉控制字符），因为落点可能是终端；落在哪个 App 写文字时无法得知（第一个经过的 App 就会读走并被缓存）。单击复制同样是图片 + 文字两条。
  - 卡片上直接显示备注（先打的字，再说的话）；麦克风标记只在有转写文字时出现；转写中显示「正在转文字…」，失败显示「没能转成文字」，右键可重试。
  - 双击：编辑备注（改文字或重录）。
  - 悬停：显示备注文字，有语音的话显示 ▶ 波形。
  - ×：删除。
- 绳子右端：「🐔 整理 N 张」和「清空」。
- 窗口：非激活 NSPanel，`sharingType = .none`（永远不会被录进去），所有桌面空间都显示，只有卡片区域接收鼠标，出现在指针所在的屏幕上。最多显示约 12 张，再多就叠起来。

## 4. 分层提速

实测（10 段真实录屏）：从停止到审核页打开要 2–10 分钟，中位数约 4.5 分钟。转写只占不到半分钟（26.8 分钟音频用了 21 秒），大头是模型读稿和挑帧。

| 层 | 做什么 | 预计收益 |
|---|---|---|
| L1 | 录制中后台转写和扫描画面：停止时转写稿已经好了 | 省 20–60 秒 |
| L2 | 录制中滚动出草稿：小模型按窗口起草条目，悬浮条里下蛋 | 最后一遍是在草稿上修改，比从头写快 |
| L3 | 停止后先写纯文字条目，**马上打开审核页**，挑帧并行做、陆续补进页面 | 等待从约 5 分钟降到 1–2 分钟，体感最明显 |
| 修复 | App 后台处理 `Not logged in` 的问题 | 省掉「回到对话里手动开始」的几分钟 |

### 文件约定（各模块之间只通过这些文件对接）

`<session>/live/`：

- `audio.pcm`：s16le、16 kHz、单声道的麦克风音频，由录制器边录边追加（约每 100 毫秒刷新一次）。暂停期间不写入，所以字节偏移 ÷ 32000 = 视频时间（视频时间同样不含暂停）。
- `transcript.jsonl`：`live.py` 写，每段定稿一行 `{"start","end","text"}`。分段和 `transcribe.py` 完全一致（Silero VAD，≤1 秒的间隙合并，单段最长取后端上限），所以同样的音频转出来逐段相同（和从 mp4 的 AAC 音轨重转相比，偶有标点级差异）；停顿约 2 秒后当前段收口，思考时的长停顿不会把句子断开。
- `drafts.jsonl`：`live.py` 写，每行 `{"id","op":"add|update|drop","kind","title","t","confidence"}`，同一个 id 以后面的行为准。
- `status.json`：`{"asr":"running|done|off|error","drafts":"running|off|error","updated":<epoch>,"note":"…"}`。
- `stop`：录制器停止时创建。`live.py` 处理完剩下的音频，写出最终的 `<session>/transcript.json`（格式和 `transcribe.py run` 完全一致），然后退出。

截图：

- `<session>/shots/<NNN>.png`（另有 `<NNN>.marked.png` 笔迹版、`<NNN>.wav` 语音备注）。
- `<session>/shots.jsonl`：每行 `{"n","file","marked","t","wall","region","voice","text","strokes"}`。录屏中截的图 `t` 是视频时间，单独截的图 `t` 为 null。
  `transcribe.py` 把语音备注转写后写进同一行的 `"said"` 字段（追加一行同 `n` 的更新，后写的为准）。
- 截图 session 的 `meta.json`：`{"mode":"shots", "engine":"native-app", …}`，没有 `recording.mp4`。

草稿模型：默认使用当前 agent 的 CLI 跑小模型（`claude -p --model claude-haiku-5-5`，或 `codex exec` 的对应命令）。配置项 `record.live_drafts: true|false`。
触发条件：新说了 ≥60 秒且有 ≥3 秒停顿，或者距上次已 3 分钟。单次超时 60 秒，失败就跳过，**绝不阻塞录制**。

审核页：`items.json` 顶层 `"processing": true` 期间每 1.5 秒轮询一次（带 ETag，没变化就是 304），之后每 5 秒一次。
agent 写的字段（`frames`、`clip`、`code_refs`、`source`、`digest` 和新增的条目）实时更新进来，正在编辑的输入框不动、不跳滚动。
页面保存的是「用户改了哪些字段」的补丁，不是整份列表，服务端在锁内合并；用户改过的字段记在条目的 `_user` 里，agent 不会覆盖（除非 `--force`）。
用户丢弃的条目保持丢弃，并掉的条目记在顶层 `_removed`，agent 再写它会被跳过（帧会补到并入的那条上）。
还没补上的帧显示加载占位，新帧淡入；顶栏显示「整理中… 已出 N 条，截图补充中」，`items.py done` 后消失。处理中也可以点「完成审核」，只提醒一次。
agent 改条目只能用 `items.py`（patch / set-frames / add / done，带锁、原子写入），不能整份覆盖 `items.json`。
锁：每个 session 一个 `.items.lock`（macOS/Linux `flock`，Windows `msvcrt.locking`），review.py 和 items.py 共用。

## 平台

- macOS：以上全部。
- Windows/Linux（Tk 录制器）：L1/L3、录屏中截图（ffmpeg 抓单帧）、`live/audio.pcm`。单独截图和鸡舍这一轮先不做。等 GCP 虚拟机可用了再一起实测。
