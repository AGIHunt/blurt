# 设计：截图模式、下蛋动效、顶部鸡舍、分层提速

2026-10-21。面向 vibe coder：一边点自己做的东西一边说，说完马上拿到能交给 agent 的条目。
总原则不变：**录制中绝不打断**；要停，只能是用户自己按的。

## 1. 截图模式：「一张图 + 一句话」

同一个概念，两个入口。快捷键 **⌥⇧A**（Windows/Linux `Alt+Shift+A`，和微信/QQ 截图的 Alt+A 一致，好记）。

### 1a. 单独截图（没在录屏时）

1. ⌥⇧A → 复用录屏的选区遮罩：拖一块 / 点一个窗口 / F 全屏 / L 上次区域。**松手即截**（像 ⌘⇧4），不需要再点「开始」。
2. 快门：选区闪一下白光（快门声默认关，设置 → 通用 → 卡片里可以打开），截图缩成卡片，弹簧动画飞到屏幕顶部的**鸡舍**（§3），挂在绳子上。
3. **自动开麦**：卡片下方弹一个小气泡，一边说，一边把听到的字用灰色显示在输入框的位置。
   - **不会自己收尾**（2026-10-31，创始人：给高效的人用的工具，这种细节必须做对）：停顿不结束备注，也没有倒计时，只在用户确认时保存。
     取代 BA-53（2026-10-30）的「说了 1 秒以上静音 3 秒收尾、不到 1 秒静音 5 秒收尾，最后 1.5 秒在『完成 ↩』内沿走一圈白线」，
     `NoteEndpointer` 为它加的 `silenceAfterShort` / `shortSpeech` / `endsIn` 一并删掉（听写和 ⌥V 语音笔记从没用到，默认值不变）。
   - 按键由 BlurtCore `NoteKeys` 决定（状态 × 按键 → 动作，`NoteKeysTests`）：
     - **↩**（或点「完成」）：保存。没打字时灰字原样采用（录音保留，卡片上的字来自同一路流式识别）；什么都没有就是不带备注的截图。
     - **⇧↩**：换行（输入框本来就是多行，⌃↩ / ⌥↩ 也换行）。灰字还在时先采用、再换行；输入框空着时什么也不做。
     - **Tab**：采用灰字——字变黑进入输入框，停止收音，光标在末尾，接着用键盘写（Tab 之后切到键盘，不再继续收音）。
       不做「Tab 之后接着听」：实时文字是一整段会被反复修正的字符串（流式分段的已定稿部分 + 正在说的部分，还有约 10 秒窗口的重听），
       不是能干净地接在键入文字后面的一段段文字。采用后，最终识别结果到了而用户还没改过，就换成最终结果，保证卡片上的字就是气泡里看到的；
       改过或提前保存，以输入框为准。没有灰字可采用时（还没开口、已经是打字备注、已经采用过），Tab 照旧打开「归入」项目列表。
     - **直接打字**：灰字还在时，打字替换它——收音停止，录音先放在一边：把字删空，灰字回来（这时 ↩ 仍然采用它）；带着打的字保存，录音删掉。
       开口前打字就是打字备注（麦克风停，什么也不留）。只有提交了的文字才算打字（输入法组字不算）。
     - **Esc**：不变。先清掉打的字（灰字会回来），再按一次丢弃这张截图（5 秒内可以撤销）。
   - 底栏状态位：开口前显示已录时长；有灰字时显示按键「Tab 采用识别结果 · 直接打字可替换」（英文 "Tab accept · type to replace"）。
     ↩ 已经写在「完成 ↩」按钮上，不重复。气泡在截图时就按「芯片 + 垃圾桶 + 这行按键 + 完成 ↩」留够宽度，字出来时不会变宽。
   - 麦克风兜底：20 秒没开口就停止收音（气泡留着，可以打字；在图上画画时顺延），总长最多 120 秒；停了以后灰字留着，等用户确认。
     切到别的 App 3 秒后保存（同时停麦，已说的保留）——不会浮在所有 App 上面，也不会在后台一直听。
     「静音」是相对房间底噪说的（v0.8，BlurtCore `NoteEndpointer`）：底噪取最近 3 秒 20 ms 帧的第 10 百分位，说话时也跟着走；
     麦克风刚打开的 0.25 秒（比房间安静）不算。
   - 用户刚截完图，气泡抢焦点可以接受；保存后焦点还给原来的 App。留下的录音一定转写；转写为空（只有房间声）就丢掉录音，卡片上不出现麦克风。
   - 「编辑备注」用同一个气泡，按键一致：↩ 保存，⇧↩ 换行，Esc 恢复原样，Tab 打开项目列表。重录也不会因为停顿结束：
     开口后底栏显示「0:04 · Tab 停止」，Tab 结束重录并保留，保存时替换原来的录音和文字。
   - 气泡开着时，截图放大预览，**按住 ⌃ 拖动**可以在图上圈画（和录屏画笔同一手势），笔迹另存一份 `*.marked.png`，原图保留。
     （v0.9-next 起改为原地标注：选区冻结在原处直接画，拖动 / ⇧ 方框 / ⌥ 椭圆，见 next-round.md K7 细则「原地标注」。）
   - 备注没收尾时再按 ⌥⇧A：先保存当前备注，再截下一张。连续截几张不需要任何确认。
   - **类型**（2026-10-31，创始人）：底栏「去处」芯片旁边一个同样样式的「类型」芯片（`KindChip.swift`），可选：
     问题 / 想法 / 笔记 / 待办（英文名取自 `kind.*`：Issue / Idea / Note / Task），不选就是「待定」，和以前一样由整理决定。
     - 没选时芯片写「类型」，配一个标签图标（不用虚线圈：虚线圈是旁边「未归类」项目的标记，两个放在一起会被看成一回事，2026-10-31）；选了显示这个类型在主窗口里的图标（`KindStyle`）和名字。
     - 点芯片在气泡里展开列表（和项目列表同一套网格）：四个类型，一条细线，「不指定 · 整理时再定」。每行右侧写着它的键
       （⌘1–⌘4、⌘0）——按键只在这里出现一次，底栏已经满了，不再加提示。当前的那行打勾，光标从它开始。
     - 按键（BlurtCore `NoteKeys` + `NoteKind`，`NoteKeysTests`）：⌘1–⌘4 设定、⌘0 清除，在三种气泡（⌥A、编辑备注、录屏中的备注）
       里任何状态都有效，列表开着也一样（设定后列表收起）；⌘5–⌘9 不归气泡。输入法组字时不接。气泡原来没有 ⌘ 数字键；主菜单的
       ⌘1–⌘4（「前往」收件箱等，主窗口用）在气泡拿着键盘时由气泡先接（`NotePanel.performKeyEquivalent`），不会切主窗口。
       列表开着时：↑↓ 移动、↩ 选中（不是保存备注）、Esc / Tab 收起回到备注（不丢弃、不采用灰字）、⇧↩ 不做事；输入焦点一直在备注框，
       直接打字照常进备注，列表收起。打开类型列表会收起项目列表，反过来也一样。
     - 宽度：气泡按最宽的类型名留出芯片位置，选类型不会让气泡变宽。录屏中的备注（没有去处芯片）把类型芯片放在底栏最左。
     - 保存：随备注一起写进 `shots.jsonl` 的 `"kind"`（`Shot.itemKind`；null = 待定）；编辑备注和录屏中的备注按 Esc，类型保持原样。
       录屏中的截图同样写进录屏 session 的 `shots.jsonl`。
     - 卡片：有类型的卡片显示它的图标——截图卡片排在麦克风、笔迹标记前面（白色，同一个小胶囊或备注条上），语音卡片在麦克风上方用
       类型颜色；卡片面板的格子里，截图在画面左下角（右上角是操作按钮），语音在麦克风左边（`CardKindMark`）。
     - 生成事项：选了类型，事项就是这个 `kind`，不管关键词猜测还是 agent 怎么判断，并记为用户设定（`_user.kind`），之后的整理、
       「AI 补全」、重新 ingest 都不会改（`items.py build_item`、`captures.py fields_for`、`frames.py marks` 的 `kind`，
       SKILL.md §3；`tests/test_captures.py`）。旧截图没有这个字段，行为不变。
4. 一批截图属于同一个 session：`<workspace 的 sessions 目录>/<ts>-shots/`，第一次截图时创建。点鸡舍上的「🐔 整理 N 张」才开始处理，处理后开新的一批。
5. 可选（菜单开关，默认关）：**收集系统截图**，把 ⌘⇧3/4/5 截的图也挂到鸡舍上（同 Tendedero），不带备注，双击可以补。

为什么要这个模式：很多反馈是一个画面加一句话，录一段视频太重了。截图是全分辨率的、就是证据本身，不用从视频里挑帧，处理会快很多。
缺点是看不到操作流程和动画，所以视频模式要保留，说明里也要讲清楚怎么选。

### 1b. 录屏中截图

需要：视频帧经过压缩，agent 挑帧靠猜。按一下截图就是「就是这一刻、就是这个画面」，信号比画笔还强，而且是全分辨率。

- 录屏中 ⌥⇧A（当时 ⌥⇧M 标记也一起升级成截图；1.0.7 去掉了 ⌥M，见下面 2026-10-31 的更新）：**不暂停，不弹输入**，直接截下录制区域的全分辨率静帧。录制区域的边框闪一下（边框不在录制范围内）。
  缩略图飞进悬浮条，悬浮条上显示 📸 计数。
- 这张图的备注就是前后大约 15 秒说的话。你本来就在说话，再停下来补录会打断思路。
- 想打字补充：点悬浮条上的 📸 打开备注框。**打开时自动暂停，关掉自动继续**，和放弃录制的确认框一样。只有主动点开才会暂停。
- agent 端：每张截图都要锚定一条条目（和画笔一样，优先级高于对模糊语句的理解），这张截图作为该条的首帧。

**2026-10-31 更新（BA-60/61/64/66，创始人录屏自测）：录屏中 ⌥A 就是普通截图。**

- 录屏中 ⌥A 走和平时完全一样的截图流程：框选、原地标注、备注（打字或说话）、挂成卡片。**录屏不暂停**，截图的过程本身也录进视频。
  `record.py snap` 保持原样（截录制区域的静帧）。刘海上的截图按钮后来也改成和 ⌥A 完全一样
  （框选、备注、卡片，录屏不停；`Island.snapWithNote` 直接走 `hotkey(.snap)`），不再截静帧、也不再暂停录屏。
- 这张截图属于这段录屏：写进录屏 session 的 `shots/NNN.png` 和 `shots.jsonl`（`t` = 视频时间，`text` / `voice` / `said`，
  `project` = 这段录屏要去的项目，备注框的「去处」可以改），`events.jsonl` 里一行 `{"type":"snap","via":"picker"}`。
  所以 `frames.py marks` 能列出它，整理时 agent 用它的备注生成条目。它不单独归档（`Snapper.settled` 对录屏里的截图只取文字）。
- 卡片：录屏期间挂在绳子上（`Shot.hangs`，只在内存里），菜单里没有「移到 / 整理」，写着「随这段录屏一起整理」；录屏结束时离开绳子。
  结束时还开着的备注先保存；还在转写的语音备注最多等 8 秒（`Snapper.takeEnded`），再交给整理。
- 语音备注和录屏同时用麦克风：录屏的音轨（macOS 15 起 ScreenCaptureKit 的麦克风输出，更早是 AVCaptureSession）和备注的
  AVAudioEngine 是同一个输入设备的两个独立客户端，CoreAudio 同时给两边送音频，说的话同时进视频和备注。
  测试里两边都用 `BLURT_TEST_MIC_WAV` 注入同一个 wav（不碰真麦克风）。
- 录屏中按听写键不开始听写，刘海说「录屏时不能听写」。
- **1.0.7 去掉了 macOS 的 ⌥M（标记这一刻）。** 原因：录屏中 ⌥A 已经不暂停、走完整的截图卡片流程，而边录边说的话本身就标出了那一刻，
  ⌥M 多余；少一个快捷键（而且 ⌥M 在 macOS 上会打出 µ）。去掉的是 App 里的快捷键、设置页那一行、刘海 ··· 菜单里的「加一个标记」、
  刘海上单独的标记计数（小旗）和放弃录屏时「N 个标记」的说法；录屏中的静帧现在只有一个计数。保留：旧录屏里的 `marker` 事件和
  `via: "marker"` 的静帧照常读（`frames.py marks` 的 `markers`、`captures.py`）；`record.py marker` 发给 App 时当作一次
  `snap`（不再记 marker 事件）；Windows / Linux 录制器（`tk_recorder.py`、Tauri）的 Alt+Shift+M 不变。

**录屏会录到口喷鸡自己（BA-60…66）。** v1.0.7 之前录屏排除了本进程的所有窗口。现在口喷鸡像别的 App 一样被录进去：主窗口、设置、
卡片、备注框、截图流程、画笔笔迹、刘海。只排除（BlurtCore `CaptureExclusion`，窗口用 `OwnWindows.mark` 标记身份）：

| 窗口 | 录屏 | 截图（⌥A / ⌥C / ⌥T） |
|---|---|---|
| 倒计时 | 排除（录屏在它消失后才开始，0.12 s 余量；万一还在屏幕上也被过滤） | — |
| 录制区域的红框 | 排除（本来就在区域外 4 pt，贴着屏幕边时也不会露一条） | 照常 |
| 刘海和它下面的字幕行 | 照常；「设置 → 通用 → 录屏时不录刘海」（`record.hide_notch`，默认关）时排除 | 照常（这个设置只管录屏） |
| 选区遮罩（变暗、放大镜、十字线）、闪光、飞行的缩略图 | 照常（截图流程要录进去） | 排除 |
| 其余（主窗口、设置、卡片、备注、画笔笔迹…） | 照常 | 照常 |

滤镜在倒计时结束后才建（`Recorder.start`），排除的窗口出现或消失时（边框、刘海、开关设置）用 `updateContentFilter` 更新；
屏幕捕获被 macOS 中断、重新开始时用同一套规则（以前重启后画笔窗口会被排除）。画笔笔迹只经由画笔窗口进视频一次：没有任何脚本再把笔画画到帧上。
测试：`BLURT_TEST_CAPTURE_SELF=1` 让录屏和截图只包含本 App 的窗口（其余为空），在有人用的 Mac 上跑脚本不会录到别的 App。
点击：`events.jsonl` 的 `click` 以前只来自全局监听（别的 App 的窗口）；口喷鸡自己的窗口现在也在视频里，所以加了本地监听，
这些点击带 `"blurt": true`。同一次按下只会到其中一个监听；BlurtCore `ClickLog` 再按时间戳和按键去重，不会记两次。

**刘海上的文字（BA-64）。** 录屏展开的刘海第二行改成大白话：「截图 6 张 · 已识别 4 个事项」（BlurtCore `TakeLine`；「已识别」是
live.py 边录边听出来的事项草稿），下一行「点完成后整理到 Atlas Web」（只在会整理时显示）。每张 ⌥A 截图也是绳子上的一张卡片。

**完成之后（BA-61）。** 结束时刘海说「正在整理到 Atlas Web」，第二行是这台 Mac 上通常要多久（「通常约 4 分钟」）：BlurtCore
`OrganizeEstimate` 用本机已整理过的整段录屏（`jobs/` 里 process 任务的起止时间，对照 meta.json 的视频时长）做稳健直线拟合
（Theil–Sen：两两斜率的中位数，斜率不小于 0，不短于最快的一次）。少于 3 次不给数字，只说「整理好后，事项会出现在那里」。
展开刘海时，正在整理的任务行显示「还剩约 N 分钟」（超过通常时长就不再显示）。整理完：「已整理到 Atlas Web · 5 条新的」+「打开」。

**只保存视频（BA-66）。** 刘海 ··· 菜单第一项和菜单栏菜单里有「只保存视频」：录屏照常保存（meta.json `video_only: true`），
不交给 agent，视频在访达里选中，刘海说「视频已保存 · 没有整理」并可再次在访达中显示。自动删除视频只删已整理的录屏，所以它不会被清理。
App 里没有「之后再整理」的入口（检查过：只有失败录屏的提示和任务重试有「整理」）；需要时让 blurt 技能处理这个 session。

## 2. 动效隐喻：下蛋，不用虫子

- **一条 = 一个蛋**。口喷鸡下蛋，天然成立，而且不分种类：
  - issue：带小虫斑点的蛋
  - idea：**金蛋**（金点子）
  - note：白蛋
  - task：带勾形纹的棕蛋
  - 自定义 lens：淡彩蛋
- 虫子只适合 issue，而且录屏时屏幕上爬虫子会让人焦虑。留给以后的「修好了」时刻：鸡把虫啄掉。
- 蛋**用代码画**（CoreGraphics 矢量：渐变、高光、斑点），不用位图素材：Retina 清晰，深色模式也好看，官网上可以用同样形状的 SVG。
- 出现的地方：
  - **录屏中**：实时草稿（§4）每识别出一条，就有一颗蛋落进悬浮条的小窝里，轻轻弹一下，显示「🥚 6」。**录屏中不出声**，否则会录进麦克风。
  - **录完 / 点了整理**：鸡舍上的蛋轻轻晃动（孵化中），整理完成后通知用户并打开审核页。
  - **审核页 / 截图卡片**：用对应种类的蛋做标识。

## 3. 顶部鸡舍（the Perch）：向 Tendedero 学习

屏幕顶部菜单栏下方一根米色麻绳（两端系在小木钉上），截图像拍立得一样被**鸡爪夹子**夹着挂在上面。鸡爪夹子是我们自己的细节，和 Tendedero 的晾衣夹区分开。

- 平时隐藏。新截了一张图时滑下来，停 3 秒后收回。指针在顶部中间区域停留超过 250 毫秒时滑下来。⌥⇧B 菜单里有「显示鸡舍」。指针离开 400 毫秒后收回。
- 动效：
  - 绳子是一根阻尼弦（Rope.swift）：挂的卡片越多越往下坠（越重越绷，下垂增长放缓），卡片坐在绳上、随所在处的坡度倾斜。挂上一张时那里一沉、绳子弹几下；拿走时弹回；悬停提起的卡片不再压着绳子，那里升起一点；鸡舍滑下来时绳子也晃一下。1–2 秒内停稳，停稳后不再逐帧刷新。
  - 卡片挂上去时像钟摆一样晃几下，然后停住（阻尼弹簧）。
  - 悬停时卡片抬起、停止摆动，左右的卡片用弹簧让位。
  - 拖出去时有惯性。删除时卡片受重力掉出屏幕。
  - 系统开了「减弱动态效果」就改成淡入淡出，绳子只有静态的下垂。
- 卡片手势：
  - 单击：复制图片（有笔迹就复制带笔迹的那张）。
  - 拖动：拖出文件，可以拖进 Claude Code、聊天窗口或 Finder；有备注的话，同时以文本形式提供。
    v0.8：图片和备注是两个独立的剪贴板条目（之前文字挂在图片那一条上，多数 App 只拿文件，文字就丢了）。拖出的文字是一行（`打的字 · 说的话`、去掉控制字符），因为落点可能是终端；落在哪个 App 写文字时无法得知（第一个经过的 App 就会读走并被缓存）。单击复制同样是图片 + 文字两条。
  - 卡片上直接显示备注（先打的字，再说的话）；麦克风标记只在有转写文字时出现；转写中显示「正在转文字…」，失败显示「没能转成文字」，右键可重试。
  - 双击：编辑备注（改文字或重录）。
  - 悬停：显示备注文字，有语音的话显示 ▶ 波形。
  - 悬停预览（2026-10-31）：卡片小，长得像的截图分不清，会拿错。备选是「放大悬停的那张卡」，但邻居会跟着挪；最后选的是
    **整行不动**，在备注文字下面接着显示这张卡的大图，用的是整行下面的屏幕空间。和文字是同一块深色面板：先文字，后图片。
    规则在 BlurtCore `CardPeek` / `CardPeekLayout`（有测试）：
    - 指针在一张卡上停 0.3 秒才出现，扫过整行不会闪；出现之后换到另一张立刻切换，不再等（和系统 tooltip 一样）；
      卡片之间的空隙里保留上一张，不闪。
    - 指针离开这一行立刻消失，下次重新等 0.3 秒。拖卡片时隐藏。
    - 以悬停卡片的 x 为中心，放不下就贴着屏幕边（留 12 pt）。图保持比例、不放大，最大为可见屏幕宽、高各一半（四分之一面积），也不超过行下方剩下的高度；小图按原尺寸显示，所以各卡片的图大小不一（1.0.7：原先最宽 360 pt、高 40 %，全屏截图看不清细节，几张相近的分不出来）。卡片面板因此占满整块屏幕高度，但只在画出内容的地方接收鼠标。
    - 语音卡片没有图。图片部分不接收鼠标，不挡拖动。
    - 冷启动时 0.15 秒淡入并从 0.97 放大到 1；开了「减弱动态效果」只淡入，不缩放。热切换没有动画，原地换内容。
  - ×：删除。
- 绳子右端：「🐔 整理 N 张」和「清空」。
- 窗口：非激活 NSPanel，所有桌面空间都显示，只有卡片区域接收鼠标，出现在指针所在的屏幕上。最多显示约 12 张，再多就叠起来。

## 4. 分层提速

实测（10 段真实录屏）：从停止到审核页打开要 2–10 分钟，中位数约 4.5 分钟。转写只占不到半分钟（26.8 分钟音频用了 21 秒），大头是模型读稿和挑帧。

| 层 | 做什么 | 预计收益 |
|---|---|---|
| L1 | 录制中后台转写和扫描画面：停止时转写稿已经好了 | 省 20–60 秒 |
| L2 | 录制中滚动出草稿：小模型按窗口起草条目，悬浮条里下蛋 | 最后一遍是在草稿上修改，比从头写快 |
| L3 | 停止后先写纯文字条目，**马上打开审核页**，挑帧并行做、陆续补进页面 | 等待从约 5 分钟降到 1–2 分钟，体感最明显 |
| 修复 | App 后台处理 `Not logged in` 的问题 | 省掉「回到对话里手动开始」的几分钟 |

### 文件约定（各模块之间只通过这些文件对接）

`<session>/live/`：

- `audio.pcm`：s16le、16 kHz、单声道的麦克风音频，由录制器边录边追加（约每 100 毫秒刷新一次）。暂停期间不写入，所以字节偏移 ÷ 32000 = 视频时间（视频时间同样不含暂停）。
- `transcript.jsonl`：`live.py` 写，每段定稿一行 `{"start","end","text"}`。分段和 `transcribe.py` 完全一致（Silero VAD，≤1 秒的间隙合并，单段最长取后端上限），所以同样的音频转出来逐段相同（和从 mp4 的 AAC 音轨重转相比，偶有标点级差异）；停顿约 2 秒后当前段收口，思考时的长停顿不会把句子断开。
- `drafts.jsonl`：`live.py` 写，每行 `{"id","op":"add|update|drop","kind","title","t","confidence"}`，同一个 id 以后面的行为准。
- `status.json`：`{"asr":"running|done|off|error","drafts":"running|off|error","updated":<epoch>,"note":"…"}`。
- `stop`：录制器停止时创建。`live.py` 处理完剩下的音频，写出最终的 `<session>/transcript.json`（格式和 `transcribe.py run` 完全一致），然后退出。

截图：

- `<session>/shots/<NNN>.png`（另有 `<NNN>.marked.png` 笔迹版、`<NNN>.wav` 语音备注）。
- `<session>/shots.jsonl`：每行 `{"n","file","marked","t","wall","region","voice","text","strokes"}`。录屏中截的图 `t` 是视频时间，单独截的图 `t` 为 null。
  App 写的行还带 `"kind"`：备注里选的类型（`issue` / `idea` / `note` / `task`，null 或没有 = 待定），生成的事项用它（2026-10-31）。
  录屏中用 ⌥A 截的图（2026-10-31 起）还带 `project`（录屏的去处，备注里可改）和备注的 `said`。
  `transcribe.py` 把语音备注转写后写进同一行的 `"said"` 字段（追加一行同 `n` 的更新，后写的为准）。
- 截图 session 的 `meta.json`：`{"mode":"shots", "engine":"native-app", …}`，没有 `recording.mp4`。

草稿模型：默认使用当前 agent 的 CLI 跑小模型（`claude -p --model claude-haiku-5-5`，或 `codex exec` 的对应命令）。配置项 `record.live_drafts: true|false`。
触发条件：新说了 ≥60 秒且有 ≥3 秒停顿，或者距上次已 3 分钟。单次超时 60 秒，失败就跳过，**绝不阻塞录制**。

审核页：`items.json` 顶层 `"processing": true` 期间每 1.5 秒轮询一次（带 ETag，没变化就是 304），之后每 5 秒一次。
agent 写的字段（`frames`、`clip`、`code_refs`、`source`、`digest` 和新增的条目）实时更新进来，正在编辑的输入框不动、不跳滚动。
页面保存的是「用户改了哪些字段」的补丁，不是整份列表，服务端在锁内合并；用户改过的字段记在条目的 `_user` 里，agent 不会覆盖（除非 `--force`）。
用户丢弃的条目保持丢弃，并掉的条目记在顶层 `_removed`，agent 再写它会被跳过（帧会补到并入的那条上）。
还没补上的帧显示加载占位，新帧淡入；顶栏显示「整理中… 已出 N 条，截图补充中」，`items.py done` 后消失。处理中也可以点「完成审核」，只提醒一次。
agent 改条目只能用 `items.py`（patch / set-frames / add / done，带锁、原子写入），不能整份覆盖 `items.json`。
锁：每个 session 一个 `.items.lock`（macOS/Linux `flock`，Windows `msvcrt.locking`），review.py 和 items.py 共用。
