# Windows 岛对齐 Mac（审计 + 实施记录）

范围：岛（收起的「耳朵」、展开后的内容：首页 / 录屏 / 语音备注 / 项目切换 / 拖放抽屉 / 提示条）、挂在岛下的卡片（线、排法、
落下与收起、悬停、点击、右键、删除与撤销、拖出与拖到项目）、边说边显示的文字面板。不含：截图后的备注气泡（snap-and-note 那位）、
听写本身（只管岛上怎么显示 `S.dictation` 和它的提示）、语音备注的录音逻辑（`voice_*` 与 `Voice` 结构归别人）、主窗口。

规格是 Mac 源码：`Capture/Island/Island.swift`、`IslandContent.swift`、`Ears.swift`、`HangingCards.swift`、`CardsOverview.swift`、
`Capture/CardDrag.swift`、`LiveTranscript.swift`，BlurtCore 的 `IslandLayout.swift`、`CardRow.swift`、`ToastQueue.swift`。
文案一字不改取自 `Resources/{en,zh-Hans}.lproj/Capture.strings(dict)`、`Main.strings`（`notify.*`）。

Windows 的岛 = Mac 在**没有刘海的屏幕**上画的那个胶囊（`Island.target` 的 `geo.notch == false` 分支：顶部居中、30 高、圆角 15、
闲时藏起来，指针在顶部中间停 250 ms 把它叫出来）。所以凡是 Mac 「刘海 / 菜单栏」专属的写法，这里按胶囊分支对齐。
只在两种情况下和 Mac 不一样：Windows 的惯例（Ctrl/Alt 不是 ⌘/⌥、「在文件资源管理器中显示」、托盘而不是菜单栏），或者系统能力
不同（见「做不到」）。

「Windows 之前」= 本分支 2026-11-02 的 `web/apps/overlays/src/island.ts` / `island.css`、`apps/desktop/src-tauri/src/island.rs`
（截图 `parity/island/before-*.jpg`）。

## 0. 先修的 bug：卡片挂到屏幕左上角

| 现象 | 原因 | 修法 | 结果 |
|---|---|---|---|
| RDP 上（2000×1250，125–150 %）截图后卡片挂在左上角 x≈0, y≈60，一半在屏外；岛本身居中 | 卡片的 x 是 JS 弹簧：新卡（`setCards` 的 still 卡）从 x = 0 出发，靠动画帧一步步走到位。岛窗口是全屏宽、透明、点不到的叠加窗，WebView2 把它当「被遮挡 / 后台」页，rAF 停、定时器被限速到 1 Hz 甚至每分钟一次，于是卡片长时间停在 x≈0（y 本来就在挂的位置，所以正好是「左上角」）。另外窗口尺寸变了（RDP 重连换分辨率、DPI 变化、换显示器）没有任何 `resize` 处理，卡片一直按旧的 `innerWidth` 排。浏览器预览里把标签页切到后台能复现（`before-cards-stuck-left.jpg`） | ① 排法移植 Mac 的 `CardRow.layout`（纯函数 `cards.ts`，有测试：100/125/150/200 %、窗口还没量出宽度、副屏）；中心取舞台宽度的一半（岛是 CSS 居中在同一个舞台上），宽度为 0 时退回屏幕宽，永远不会是 0。② 新卡、窗口尺寸变化时 x 直接放到位（不从 0 滑过来）。③ 帧间隔超过 250 ms（页面被限速）时弹簧直接落到目标，不再半路停住。④ `resize` / `ResizeObserver` 重新排 || 已修：`cards.ts` + `tests/cards.test.ts`（100/125/150/200 %、宽度 0、副屏）；另外帧循环本身有个会自我繁殖的 bug（每个 50 ms 兜底定时器会多分出一条 rAF 链，越动越多，被限速时定时器队列被灌满，卡片的帧和点击后的复制都等不到），已改成同时只有一条链；Playwright 前台驱动 + 后台标签页里都验证居中（`drive.mjs`） |
